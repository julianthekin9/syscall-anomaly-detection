# LID-DS 2021 → нативный формат проекта

Экспериментальная часть, не входит в пакет `syscall_hids`. Скрипт самостоятельный: только stdlib, код проекта не импортирует. Его единственная задача — превратить LID-DS в такую же раскладку и формат, какие пишет eBPF-коллектор, чтобы дальше данные шли через общий интерфейс (`hids-train`, `hids-eval`) без каких-либо веток "если это LID-DS".

## Запуск

```bash
python experiments/lid_ds/convert.py /path/to/LID-DS-2021 ./DATASET_LIDDS --pre-attack-to-normal
# быстрая проверка на 3 записях каждого сплита одного сценария:
python experiments/lid_ds/convert.py /path/to/LID-DS-2021 ./DATASET_LIDDS --scenarios CVE-2017-7529 --limit 3
```

Затем в `config.py` (или в YAML после этапа 3) указать `DATASET_ROOT = "./DATASET_LIDDS"`.

## Что делает

| LID-DS 2021 | Результат |
|---|---|
| `<сценарий>/training/*.zip` | `<сценарий>/training/*.sc` |
| `<сценарий>/validation/*.zip` | `<сценарий>/validation/*.sc` |
| `test/*.zip` без эксплойта | `test/normal/*.sc` |
| `test/*.zip` с эксплойтом | `test/abnormal/<имя>.sc`: только сегмент от первого `time.exploit[].absolute` до конца записи |
| то же, часть до эксплойта | `test/normal/<имя>__pre.sc`, только с `--pre-attack-to-normal` |

- Строка `ts uid pid process tid syscall dir params` (8 колонок) превращается в `ts process syscall dir params`, то есть в формат eBPF-коллектора.
- zip читается потоково, `.sc` целиком в память не загружается.
- `manifest.json` в каждом сценарии хранит для каждой записи источник, время эксплойта, число строк в каждом выходном файле и статус. По нему можно восстановить, откуда взялся каждый файл.
- Записи с эксплойтом в training/validation пропускаются и помечаются в манифесте.

## Почему атака вырезается в отдельный файл

В LID-DS атакующая запись в основном состоит из нормального трафика, атака в ней короткая. Ядро проекта размечает тестовые окна по папке (`abnormal` значит атака). Если положить запись целиком, большинство «атакующих» окон на деле окажутся нормальными, и AUC занижается (так было, когда AUC упал до ~0.66). После разрезки разметка по папке становится верной, и ядру не нужно знать про время атак.

## Ограничения

- Атака считается длящейся от первого эксплойта до конца записи. Если эффект атаки заканчивается раньше, хвост будет размечен как атака.
- Сегменты разных записей в один файл НЕ склеиваются: на стыке получились бы окна с искусственным переходом между процессами, которого в реальности не было.
- Признак `arg_count` в LID-DS и в eBPF-данных означает разное. В sysdig число параметров зависит от syscall, а eBPF-коллектор всегда пишет 6 аргументов на вход и `res` на выход. Модели, обученные на разных источниках, поэтому несовместимы, но в пределах одного источника это не проблема.
