# Дополнительные критерии выбора рабочей точки

Задание для Claude Code. Вместо `docs/CALIBRATE_COUNT_STREAM.md` (отложено, не выполнять) добавить в `hids-calibrate` новые критерии выбора рабочей точки, кроме F_β и recall@FPR. Методы оценки окна остаются прежние (`nll`, `topk`, `run_nll`, `run_rank`). Всё считается из кеша, модель не прогоняется.

## Зачем
F_β зависит от доли атак в тесте (π) и вырождается в «тревогу на всё», когда π ≈ 0.5 (см. CALIBRATE_OBJECTIVE.md). Нужны критерии, которые по-разному взвешивают пропуски и ложные тревоги, чтобы показать, как от критерия зависит выбранная точка и вывод о лучшем методе.

## Новые значения `--objective`
Все считаются векторно по сетке из TP/FP/FN/TN (TPR = recall, FPR, TNR = 1 − FPR, FNR = 1 − TPR).

| Ключ | Что максимизируется / минимизируется | Зависит от π | Значение у «тревоги на всё» |
|---|---|---|---|
| `youden` | J = TPR − FPR (эквивалентно balanced accuracy = (TPR + TNR)/2) | нет | 0 |
| `mcc` | коэффициент корреляции Метьюза (MCC) | да, но устойчив к дисбалансу | 0 |
| `gmean` | G-mean = √(TPR · TNR) | нет | 0 |
| `eer` | точка равных ошибок: минимум \|FPR − FNR\|; при равенстве — меньшая сумма FPR + FNR | нет | — |
| `cost` | минимум ожидаемой стоимости `c_fn · FN + c_fp · FP` | да | — |

Плюс уже существующие: `fbeta` (с `--beta`), `fbeta_prevalence`, `recall_at_fpr`.

- `cost`: флаги `--cost_fn` (по умолчанию 10) и `--cost_fp` (по умолчанию 1), то есть пропуск атаки в 10 раз дороже ложной тревоги. Значения записывать в JSON.
- MCC при нулевом знаменателе = 0 (как в sklearn).
- `--max_fpr` работает как ограничение для **любого** критерия, как сейчас для `fbeta`.
- Сглаживание 3×3 и предупреждение о краю сетки — для всех критериев одинаково.
- Проверка `degenerate` обобщается: для каждого критерия считается его значение у «тревоги на всё» и у «нет тревог». Точка помечается вырожденной, если она не лучше обоих тривиальных детекторов больше чем на `--degenerate_margin` (по умолчанию 0.01 в единицах критерия), или если её FPR(calib) > 0.5. Для `youden`, `gmean`, `mcc` у тривиальных детекторов значение 0, так что на сбалансированном тесте эти критерии в «тревогу на всё» не вырождаются. Это нужно отметить в docstring.

## Что выводить
Для каждой пары (метод, критерий) на holdout — **одинаковый полный набор метрик**, независимо от того, по какому критерию выбрана точка: параметры, порог, TP, FP, FN, TN, precision, recall (TPR), FPR, FNR, F1, MCC, J, G-mean, стоимость, pAUC@0.05, ROC-AUC, бутстреп-ДИ для F1, MCC, J, recall, FPR. Так видно, как точка, выбранная по одному критерию, выглядит по остальным.

- `comparison.csv`: строка на (сервис, метод, критерий, max_fpr).
- Консоль: для каждого сервиса таблица «метод × критерий», в ячейке recall / FPR выбранной точки, плюс отдельная таблица полной матрицы ошибок для основного критерия.
- **`operating_points_roc.png`** — главный новый график. Для каждого метода — его ROC-кривая на holdout, на ней маркерами отмечены точки, выбранные разными критериями (разная форма маркера на критерий, одинаковая для всех методов). Ось FPR в логарифмическом масштабе от 10⁻³ до 1. Так одним взглядом видно, куда каждый критерий двигает порог. Если методов много, сделать сетку подграфиков (по одному на метод) с общей легендой критериев.
- **`criteria_comparison.png`**: для каждого критерия — сгруппированные столбцы F1 и MCC на holdout по методам с ДИ. Или другой вид, если покажешь в плане, что он нагляднее.

## Подписи (украинский)
| Ключ | Подпис |
|---|---|
| `fbeta` (β=1) | `F1` |
| `fbeta_prevalence` | `F1 з перерахунком на частку атак` |
| `recall_at_fpr` | `Повнота при FPR ≤ α` |
| `youden` | `Індекс Юдена` |
| `mcc` | `Коефіцієнт кореляції Метьюза (MCC)` |
| `gmean` | `Середнє геометричне (G-mean)` |
| `eer` | `Точка рівних помилок (EER)` |
| `cost` | `Мінімум вартості помилок` |

Оси ROC: `Частка хибних тривог (FPR)`, `Частка виявлених атак (TPR)`. Заголовок: `Робочі точки, обрані різними критеріями`.

## Тесты
- значения всех критериев совпадают со sklearn / ручным расчётом на случайных матрицах ошибок (MCC — `matthews_corrcoef`, balanced accuracy — `balanced_accuracy_score`);
- на синтетике со сбалансированным тестом и слабым сигналом `fbeta` (β=2) выбирает «тревогу на всё», а `youden`, `gmean`, `mcc` — нет;
- `eer`: на синтетике с известными распределениями выбранная точка даёт |FPR − FNR| меньше шага сетки;
- `cost` при `c_fn = c_fp` совпадает с минимумом числа ошибок (FN + FP);
- ограничение `--max_fpr` соблюдается для каждого критерия;
- регрессия: результаты `fbeta` и `recall_at_fpr` не меняются.
