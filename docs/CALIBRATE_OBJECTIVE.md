# Критерий выбора рабочей точки: F1 (+ ограничение FPR)

Задание для Claude Code. Расширение `hids-calibrate`. Основной критерий выбора рабочей точки меняется с F2 на **F1**. Дополнительно вводится ограничение FPR и проверка «не хуже ли тривиального детектора».

## Почему
На тесте с долей атак π ≈ 0.5 детектор «тревога на каждом окне» получает F2 = 5π/(4π+1) ≈ 0.83 — больше, чем любой реальный метод. Поэтому калибровка по F2 тянет все методы к «тревоге на всё», и серийные методы туда дошли. У F1 тривиальный уровень ниже: 2π/(π+1) ≈ 0.67. Детектор с осмысленным сигналом его превосходит (пример: recall 0.7 при FPR 1% даёт F1 ≈ 0.82). Но на сервисах со слабым сигналом (ROC-AUC 0.5–0.6) максимум F1 по-прежнему может оказаться «тревогой на всё». Поэтому нужны защита и ограничение FPR.

## Флаги
- `--objective {fbeta, fbeta_prevalence, recall_at_fpr}`, по умолчанию `fbeta`. Параметр можно передать несколько раз: тогда каждый критерий даёт свой блок результатов.
  - `fbeta`: максимум F_β на calib (как сейчас);
  - `fbeta_prevalence`: максимум F_β, пересчитанного на `--prevalence` (формула precision(π) из CALIBRATE_F2.md);
  - `recall_at_fpr`: максимум recall при FPR(calib) ≤ `--max_fpr`; при равном recall — меньший FPR.
- `--beta`: значение по умолчанию меняется на **1**. `--beta 2` воспроизводит прежние результаты.
- `--max_fpr` (список, по умолчанию пусто для `fbeta` / `fbeta_prevalence`, `0.01 0.05` для `recall_at_fpr`). Если задан вместе с `fbeta` или `fbeta_prevalence`, это **ограничение**: максимум F_β только среди точек с FPR(calib) ≤ max_fpr.
- Сглаживание 3×3 применять к значению критерия только среди допустимых точек. Если допустимых точек нет — WARNING и метод помечается `infeasible`.

## Защита от вырождения
- Для каждого метода на calib и holdout считать тривиальный уровень `F_β(тривога на все) = (1+β²)π / (β²π + 1)` при фактическом π.
- Если у выбранной точки FPR(calib) > 0.5 или F_β не выше тривиального уровня больше чем на 0.01 — WARNING `degenerate: не краще за тривогу на все вікна`, флаг `degenerate: true` в JSON и пометка `*` в консольной таблице.
- В `comparison.json`, консоли и на графике сравнения — строка или линия «тривога на все вікна». Подпись на графике: `Тривога на кожне вікно`.

## Подписи и имена
Везде, где сейчас жёстко написано «F2» (имена файлов, колонки, подписи графиков на украинском, ключи JSON), использовать фактическое β: `F1`, `F2` и т.д. Имена файлов: `f{β}_heatmap.png`, `f{β}_comparison.png`. Ключи JSON — `fbeta` плюс поле `beta`. Подписи графиков: `F1 на калібрувальній частині`, `F1 на відкладеній частині` и т.д.

## Расширить сетку перцентилей
При ограничении FPR ≤ 1% нужны пороги выше 99.9. Особенно это касается серийных методов: при m = 1 доля тревог на нормальном окне ≈ 1 − (p/100)^64, и для 1% нужно p ≈ 99.98.
- `--p_grid` по умолчанию: 90–99 с шагом 0.5, затем 99.0–99.9 с шагом 0.1, затем 99.9–99.999 логарифмически (около 10 точек).
- Тепловые карты рисовать по оси «частка вище порогу» (100 − p) в логарифмическом масштабе, подпись `Частка кроків/вікон вище порогу на валідації, %`.

## Сравнение без выбора точки
Для каждого метода и сервиса на holdout:
- ROC-AUC (уже есть);
- **pAUC при FPR ≤ 5%** (`sklearn.metrics.roc_auc_score(max_fpr=0.05)`, нормировка McClish — указать в JSON). Для серийных методов кривая строится по `R` при шаговом `p`, выбранном на calib по pAUC;
- бутстреп-ДИ и парная разность к `nll`.

## Метрики на уровне записи (для выбранной точки)
- доля атакующих записей holdout, в которых есть хотя бы одна тревога;
- доля нормальных записей holdout, в которых есть хотя бы одна тревога;
- медианная задержка до первой тревоги от начала атакующего файла (= начало атаки по соглашению формата), в секундах.

Для всех трёх — бутстреп-ДИ по записям.

## Выход
- `comparison.csv`: `objective`, `beta`, `max_fpr`, метод, параметры, recall, FPR (calib и holdout), precision, F_β, F_β@prevalence, тривиальный F_β, `degenerate`, pAUC@0.05, ROC-AUC, метрики записей, задержка, ДИ, Δ к nll.
- `f1_comparison.png` (по β): F_β на holdout по методам с ДИ и линией тривиального уровня.
- `recall_at_fpr.png`: если был запуск `recall_at_fpr`.
- `hids-calibrate-summary` учитывает новые колонки.

## Тесты
- `--beta 2 --objective fbeta` без `--max_fpr` воспроизводит нынешние `calibration.json` (регрессия);
- на синтетике, где «тревога на всё» — максимум F2, но не F1, при `beta=1` выбирается содержательная точка;
- `degenerate` срабатывает, когда сигнала нет (случайные оценки);
- ограничение `--max_fpr` соблюдается на calib; `infeasible`, когда допустимых точек нет;
- pAUC совпадает с sklearn;
- метрики на уровне записи на ручном примере.
