# Сравнение методов оценки аномальности под F2

Задание для Claude Code. Расширение `hids-calibrate` (см. `docs/CALIBRATE_F2.md`): кроме текущего метода (NLL + квантиль окна) добавить ещё два семейства методов. Для каждого подбираются свои два параметра под максимум F2 по той же методике, и в конце строится сравнение. Это материал для раздела диплома о сравнении методов, поэтому методика для всех методов должна быть одинаковой.

## Методы

Обозначения: окно из `L_w` шагов (= `seq_len` модели); на шаге `t` модель выдаёт распределение по следующему syscall, `y_t` — настоящий следующий syscall.

### 1. `nll` — NLL + квантиль окна (есть сейчас)
- оценка шага: `s_t = −log P(y_t)`;
- оценка окна: `S = quantile_q(s_1..s_L)` (или `mean`);
- порог: `θ = percentile_p` оценок окон на validation;
- окно аномально, если `S > θ`;
- сетка: `q × p`. Поведение должно остаться прежним (см. «Регрессия»).

### 2. `topk` — ранг настоящего вызова (top-k) + квантиль окна
- оценка шага: ранг настоящего вызова среди предсказаний модели, `r_t = 1 + #{j : logit_j > logit_{y_t}}`. Значение 1 — модель считала этот вызов самым вероятным. Шаг — «промах top-k», если `r_t > k`;
- оценка окна: `S = quantile_q(r_1..r_L)` (или `mean`), тот же параметр `q`, что и в методе 1;
- порог: `θ = percentile_p` оценок окон на validation;
- окно аномально, если `S > θ`. Смысл: «более `(1−q)`-й доли вызовов окна не попали в top-k», где `k = ⌊θ⌋` определяется перцентилем `p`. Эффективное `k` записывать в результаты (`k_eff`);
- сетка: `q × p`;
- ранги дискретны, поэтому на тепловой карте будут ступени и одинаковые пороги для соседних `p`. Это ожидаемо, не баг. Отметь это в docstring.

### 3. `run` — серия аномальных вызовов подряд
- аномальный вызов: шаг аномален, если его оценка выше `τ = percentile_p` оценок **шагов** на validation (перцентиль по всем шагам всех val-окон, а не по окнам);
- оценка окна: длина самой длинной серии подряд идущих аномальных шагов в окне, `R ∈ [0, L_w]`;
- окно аномально, если `R ≥ m`, где `m` — минимальная длина серии. Это параметр окна вместо квантиля. Порог по оценкам окон здесь не нужен: роль порога играет сам `m`;
- сетка: `m × p`. По умолчанию `m ∈ {1..32}`, `p` от 90.0 до 99.9 с шагом 0.1 (сетка шагового перцентиля);
- два варианта оценки шага (флаг `--run_step_score`, по умолчанию оба):
  - `run_nll`: оценка шага — NLL;
  - `run_rank`: оценка шага — ранг `r_t` (то есть «промах top-k» с `k` из перцентиля).
- серии считаются внутри окна и не переходят через границу окон (test нарезан без перекрытия). Это ограничение метода, его нужно указать в docstring.

### Флаг выбора методов
`--methods nll topk run_nll run_rank` (по умолчанию все). Каждый метод можно запустить отдельно.

## Единая методика для всех методов (обязательно)
- **Одно и то же деление calib/holdout** для всех методов (`--split_seed`): сравнение честное, только если методы оцениваются на одних и тех же записях.
- Подбор параметров — на `calib`, итог — на `holdout`. Выбор точки — через сглаживание 3×3, как сейчас. Предупреждение о выборе на краю сетки — для каждого метода.
- Бутстреп по записям на holdout — **с одними и теми же ресемплами для всех методов** (сгенерировать индексы один раз). Тогда кроме интервалов для каждого метода можно посчитать **парные разности** `ΔF2 = F2(метод) − F2(nll)` с 95% интервалом. Если интервал не содержит 0, разница значима. Это главный результат сравнения.
- Пересчёт precision и F2 на `--prevalence` — для каждого метода.
- ROC-AUC на holdout для выбранного параметра окна каждого метода. Для `run`: при выбранном `p*` оценка окна = `R`, AUC по ней.

## Кеш
К NLL по шагам добавить **ранги по шагам** для val и test: `int32 [n_windows, steps]`, считать в том же проходе модели (`(logits > logits.gather(-1, y)).sum(-1) + 1`). Повысить версию формата кеша. Старый кеш без рангов считается устаревшим и пересчитывается автоматически.

## Производительность
- `run`: для каждого `p` булева матрица `[N_w, L_w]` и максимальная серия векторно по окнам (цикл по `L_w` шагам: `cur = (cur + 1) * b_t; best = max(best, cur)`). Цикл по окнам или по `m` в Python запрещён. Для всех `m` сразу использовать то, что «окно аномально при `R ≥ m`»: гистограмма `R` по классам даёт TP/FP для всех `m` через накопленную сумму.
- `topk`: те же функции, что и для `nll`, только на матрице рангов.
