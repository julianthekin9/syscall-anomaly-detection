# Калибровка по «середине» записей и баланс 50/50

Задание для Claude Code. Расширение `hids-calibrate`: флаги, которые исключают из оценки начало нормальных записей и хвост атакующих сегментов, а также выравнивают классы до 50/50 отдельно в calib и в holdout. Всё работает для всех методов (`nll`, `topk`, `run_nll`, `run_rank`).

## Зачем
Аудит разметки (`docs/LABEL_AUDIT_REPORT.md`) показал:
- в `test/abnormal` атакой считается всё от эксплойта до конца записи, и в хвосте лежит нормальный трафик с меткой «атака»;
- нормальные окна с самыми высокими оценками, вероятно, стоят в начале записей (артефакт старта).

Флаги позволяют оценить детектор без этих искажений и посмотреть, насколько от них зависит результат.

## Флаги (все по умолчанию выключены: поведение без флагов не меняется)

| Флаг | Применяется к | Смысл |
|---|---|---|
| `--trim_head_sec H` | validation и `test/normal` | исключить окна, которые начинаются раньше `H` секунд от начала записи |
| `--trim_tail_sec T` | validation и `test/normal` | исключить окна, которые заканчиваются позже `длительность − T` |
| `--attack_max_sec A` | `test/abnormal` | оставить только окна, которые **начинаются** в первые `A` секунд атакующего сегмента (= после эксплойта); хвост дальше `A` исключить |
| `--attack_skip_sec S` | `test/abnormal` | исключить первые `S` секунд атакующего сегмента. По умолчанию 0. При `S > 0` выводить WARNING: сразу после эксплойта находятся самые атакующие окна, и их исключение занижает recall |
| `--balance {none,subsample,weight}` | calib и holdout отдельно | выравнивание классов до 50/50 (см. ниже), по умолчанию `none` |

Почему начало и хвост обрезаются у разных классов: атакующий файл начинается ровно в момент эксплойта (так режет конвертер), поэтому артефакта старта записи у него нет, а его начало — самая важная часть атаки. Артефакт старта бывает только у записей, которые начинаются с начала записи: validation и `test/normal`. Это нужно описать в docstring и в README к калибровке.

**Validation обрезается так же, как `test/normal`.** Иначе порог-перцентиль будет посчитан по распределению со стартовыми окнами, а применён к распределению без них.

## Как реализовать (без повторного прогона модели)
1. **Кеш.** Для каждого окна val и test сохранять время его первой и последней строки **относительно начала файла** (секунды, float32) и длительность файла. Новая версия формата кеша, старый пересчитывается автоматически. Времена брать из `ParsedLine.timestamp` тех же строк, из которых `make_sequences` строит окно. Не писать свою нарезку: если `make_sequences` не возвращает позиции окон, вычисли их по той же формуле (шаг и прижатие последнего окна к концу) в одной функции и проверь тестом, что позиции совпадают с содержимым окон.
2. **Фильтры** применяются к уже посчитанным окнам маской: после деления на calib и holdout и до подсчёта метрик. Модель не нужна, поэтому разные значения `H`, `T`, `A` можно перебирать быстро.
3. **Самопроверка порога из чекпоинта** выполняется **до** фильтров, на полных данных, как сейчас. С фильтрами порог по определению будет другим.
4. **Метод `run`:** перцентиль шагов на val считается по шагам только оставшихся после фильтра окон.

## Баланс 50/50
Выполняется после фильтров, отдельно в calib и в holdout.
- `subsample`: случайно убрать окна **большего** класса (обычно нормального, но после `--attack_max_sec` может оказаться наоборот; какой класс уменьшался — писать в лог и JSON), пока классов не станет поровну. Детерминированно от `--split_seed`. Отбор равномерный по окнам, при этом записи не выпадают целиком без необходимости.
- `weight`: окна не выбрасываются; окнам меньшего класса даётся вес, чтобы суммарные веса классов были равны. TP/FP/FN/TN считаются взвешенно (precision, recall, FPR, F2 — из взвешенных сумм). ROC-AUC и PR-кривые — через `sample_weight` sklearn. Бутстреп ресемплирует записи, как раньше, и веса пересчитываются внутри каждого ресемпла.
- В обоих режимах записывать в JSON число окон каждого класса до и после, фактическую долю атак π и режим.

## Выход
- Папка результатов автоматически получает суффикс из параметров, чтобы запуски не перезаписывали друг друга: `{out_dir}/{service}/h{H}_t{T}_a{A}_s{S}_{balance}/<метод>/...` (`none` — для выключенных значений).
- В `calibration.json` и `comparison.json` добавить блок `filters`:
  - значения флагов;
  - сколько окон каждого класса убрано каждым фильтром в calib и holdout;
  - итоговые π;
  - режим баланса.
- В консольную таблицу добавить строку с фильтрами и π.
- В заголовок или подпись каждого графика добавить короткую строку с фильтрами на украинском, например: `Без перших 10 с нормальних записів; атака — перші 30 с; баланс 50/50 (підвибірка)`. Без фильтров ничего не добавлять.

## Сводка по нескольким запускам
Новая команда `hids-calibrate-summary --root {out_dir}/{service}`: собирает `comparison.json` всех подпапок в одну таблицу `summary.csv` (фильтры, метод, F2/recall/FPR на holdout с ДИ, π) и строит `f2_vs_attack_max.png` — F2 на holdout в зависимости от `A` для каждого метода. Это график чувствительности к длине атакующего сегмента. Подписи на украинском: ось X `Тривалість атакуючого сегмента, с`, ось Y `F2 на відкладеній частині`, легенда — названия методов из CLAUDE.md / CALIBRATE_METHODS.md, значение «без обмеження» отметить на оси отдельно.

## Тесты
- без флагов результаты совпадают с текущей версией (регрессия: сравнить `calibration.json` всех методов на фикстурах);
- позиции и времена окон совпадают с содержимым окон из `make_sequences`;
- фильтры на синтетике: окна в первые `H` с нормальных записей и после `A` с атакующих исключены, остальные на месте; validation фильтруется вместе с `test/normal`;
- `subsample` даёт ровно 50/50 и детерминирован;
- `weight`: взвешенные метрики на синтетике совпадают с метриками на явно продублированных окнах (при целочисленных весах);
- `hids-calibrate-summary` на двух фиктивных запусках собирает таблицу и график.
