# Калибровка агрегации окна и порога под F2

Задание для Claude Code. Новая самостоятельная команда `hids-calibrate`. Она берёт обученную модель, прогоняет test, подбирает квантиль агрегации окна `q` и перцентиль порога `p` так, чтобы F2 был максимальным, и честно оценивает результат на отложенной части.

Существующие модули (`tools/train.py`, `tools/evaluation.py`, `cli/eval_recordings.py`, `modules/*`, `data/*`) НЕ меняются. Если для работы скрипта их нужно поменять, остановись и спроси.

## Методика (это важно для диплома, не упрощай)

1. **Перцентиль порога считается по нормальным окнам validation**, как в обучении: `threshold = percentile(val_window_scores(q), p)`. Метки атак при этом не нужны. `p` остаётся интерпретируемым: ожидаемая доля ложных тревог на норме примерно равна `(100 − p)%`.
2. **`q` и `p` подбираются совместно.** Распределение оконных скоров зависит от `q`, поэтому для каждого `q` значения val-скоров и порог пересчитываются.
3. **Подбор на тесте с утечкой запрещён.** Test делится **по записям** (не по окнам: соседние окна почти одинаковы) на две части со стратификацией normal/abnormal:
   - `calib`: на ней ищется максимум F2;
   - `holdout`: на ней считаются итоговые метрики, при подборе её не трогают.

   По умолчанию 50/50, `--seed 0`. Списки файлов обеих частей сохраняются в результат.
4. **Выбор точки устойчивый.** Атакующих окон мало, и одиночный пик F2 на сетке шумный. Поэтому выбирается точка с максимумом F2, сглаженного средним по окрестности 3×3 в сетке (q, p). Сырой максимум тоже записывается в отчёт.
5. **Базовая линия** — текущие `window_agg`, `window_agg_quantile` и порог из чекпоинта, посчитанные на том же `holdout`. Так видно, что дала калибровка.

## Как считать быстро

Самое дорогое — проход LSTM, и от `q` и `p` он не зависит.
- Один проход модели: для каждого окна val и test посчитать NLL **на каждом шаге** (массив `[n_windows, steps]`, float32). Использовать те же функции нарезки окон и `compute_step_scores`, что и `eval_recordings` и обучение (тест: без перекрытия, val: как при калибровке порога в обучении). Не писать свою нарезку.
- Кешировать в `{out_dir}/cache_{service}.npz` вместе с метками окон и индексом записи для каждого окна. При повторном запуске с тем же чекпоинтом (сверка по sha256 файла) брать кеш. Флаг `--no_cache` отключает кеш.
- Дальше вся сетка — это numpy: `np.quantile(step_nll, q, axis=1)`, порог, сравнение. Модель больше не нужна.
- Память: обрабатывать записи потоково, как в существующей оценке. Не держать в памяти список Python-объектов на окно.

## Сетка (значения по умолчанию, всё меняется флагами)
- `--q_grid`: `0.5 0.6 0.7 0.75 0.8 0.85 0.9 0.95 0.99 1.0` (1.0 — то же, что `max`);
- `--include_mean`: дополнительно агрегация `mean` как отдельная строка сетки, по умолчанию да;
- `--p_grid`: от 90.0 до 99.9 с шагом 0.1.

## Что считать для каждой точки и для итоговой
На `calib` для каждой (q, p): TP, FP, FN, TN, precision, recall (TPR), FPR, F1, F2.

Для выбранной точки и для базовой линии на `holdout`: всё то же плюс ROC-AUC (для данного `q`), доля атакующих окон π и precision/F2, пересчитанные на реалистичную долю атак `--prevalence 0.01` по формуле:

    precision(π) = TPR·π / (TPR·π + FPR·(1−π))

Выводится одной строкой с явной пометкой «пересчёт».

## Выход (`--out_dir`, по умолчанию `{work_dir}/calibration/{service}`)
- `calibration.json`:

  - пересчёт на `--prevalence`.

## Тесты (`tests/test_calibration.py`)
- `fbeta` совпадает с `sklearn.metrics.fbeta_score` на случайных метках;
- `aggregate(..., q=1.0)` совпадает с `max`, `q=0.5` с медианой;
- `split_recordings` детерминирован при одном seed, не пересекается и сохраняет обе группы в каждой части;
- на синтетике (атаки дают более высокий NLL) `grid_search` находит точку с F2 выше, чем у заведомо плохого порога;
- `smooth_select` на сетке с одиночным выбросом выбирает плато, а не выброс;
- end-to-end на фикстурах `tests/golden/` с `FIXT.pt` (или `FLASK.pt`): команда отрабатывает, создаёт все файлы, `calibration.json` валиден.

Существующие тесты остаются зелёными.
