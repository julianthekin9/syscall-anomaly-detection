# Задача: настраиваемый выбор входных признаков модели

Сейчас `SyscallLSTM` на вход всегда получает 4 признака:

| Признак     | Размерность embedding |
|-------------|-----------------------|
| `syscall`   | 16                    |
| `process`   | 8                     |
| `direction` | 2                     |
| `arg_count` | 4                     |

Их эмбеддинги конкатенируются в вектор размерности 30. Нужно, чтобы набор признаков задавался в конфиге и переопределялся из CLI. Это нужно для ablation-экспериментов: какой вклад каждого признака в AUC и F1.

## Требования

### 1. Конфиг

- Добавь параметр `features`: список из `{syscall, process, direction, arg_count}`. По умолчанию все четыре, чтобы текущее поведение не изменилось.
- `syscall` обязателен: это ещё и целевая переменная (предсказание следующего вызова). Если его нет в списке, падай с понятной ошибкой при валидации конфига.
- Неизвестные имена признаков и дубликаты тоже дают ошибку валидации.
- Параметр живёт там же, где остальные гиперпараметры модели. Если конфиг уже в YAML, добавь его туда и сделай CLI-override (например, `--features syscall,process`). CLI имеет приоритет над файлом.

### 2. Модель

- Создавай `nn.Embedding` только для выбранных признаков.
- Входную размерность LSTM считай динамически как сумму размерностей выбранных эмбеддингов, а не константой 30.
- Размерности эмбеддингов (16/8/2/4) не меняй.
- Порядок конкатенации фиксированный (канонический порядок признаков), а не порядок из конфига. Тогда один и тот же набор признаков всегда даёт одинаковую раскладку.

### 3. Чекпоинт

- `features` сохраняется в `ModelHParams` и сериализуется вместе с остальными hparams.
- `from_checkpoint` остаётся прямым `cls(**checkpoint["hparams"])`, без fallback'ов и без совместимости со старыми чекпоинтами.
- Если `state_dict` меняет структуру, инкрементируй `ARCHITECTURE_VERSION` в `model.py`. Если не меняет, не трогай его и объясни почему.

### 4. Данные и инференс

- Dataset/DataLoader может по-прежнему готовить все колонки, но модель использует только выбранные. Если невыбранные признаки легко не хранить в памяти (последовательности лежат в numpy `int16`), не храни их. Но не переписывай ради этого пайплайн данных.
- `predict.py`, `probe_eval.py` и `realtime_detect.py` берут набор признаков из чекпоинта, а не из текущего конфига. Модель, обученная на подмножестве признаков, должна корректно скориться всеми этими скриптами.

### 5. Логирование

- Выводи набор признаков в лог обучения при старте.
- Включи его в имя run'а или директории вывода, чтобы результаты ablation не перезаписывали друг друга (например, `feat-syscall+process`).

## Ограничения

- Минимальный объём правок: трогай только то, что нужно для этой фичи. Не рефактори соседний код, не меняй скоринг (NLL, `WINDOW_AGG`, порог) и не переименовывай ничего постороннего.
- Не оставляй мёртвый код, старые константы и закомментированные куски. Например, удали константу входной размерности 30, если она больше не нужна.
- Комментарии в коде пиши на украинском.
- Сначала изучи текущий код (config, model, dataset, train, predict, probe-скрипты) и покажи план: какие файлы и что именно меняешь. Начинай правки только после моего подтверждения.
