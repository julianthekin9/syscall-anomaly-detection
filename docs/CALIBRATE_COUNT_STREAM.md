# Два новых способа оценки окна: счётчик и скользящее окно по потоку

Задание для Claude Code. Добавить в `hids-calibrate` методы `cnt_nll`, `cnt_rank`, `stream_nll`, `stream_rank`. Всё считается из кеша (NLL и ранги по шагам), повторный прогон модели не нужен. Методика (split, критерии, фильтры, бутстреп, сравнение) — общая с остальными методами, ничего отдельного.

## Метод `cnt` — счётчик аномальных вызовов в окне
Источник: «locality frame count» в STIDE (Warrender, Forrest, Pearlmutter, IEEE S&P 1999).
- аномальный вызов: оценка шага выше `τ = percentile_p` оценок **шагов** на validation (так же, как в `run_*`);
- оценка окна: `C` — **количество** аномальных шагов в окне, не обязательно подряд, `C ∈ [0, L_w]`;
- окно аномально, если `C ≥ m`;
- сетка `m × p`: `m ∈ {1..L_w}` (по умолчанию 1..64), `p` — та же расширенная сетка, что у `run_*`;
- варианты оценки шага: `cnt_nll` (NLL) и `cnt_rank` (ранг);
- TP/FP для всех `m` сразу — через гистограмму `C` по классам и накопленную сумму, как у `run`;
- санити: при `m = 1` решения `cnt_*` и `run_*` совпадают (в окне есть хотя бы один аномальный шаг). Это тест.

## Метод `stream` — скользящее окно по потоку вызовов
Источник: блоки `StreamAverage` / `StreamMaximum` / `StreamSum` фреймворка LID-DS (`algorithms/features/impl/stream_*.py`).
- оценки шагов одной записи склеиваются в непрерывную последовательность по позиции в записи. Над ней считается скользящая статистика по последним `W` шагам: `avg` (среднее) или `max`. `sum` для фиксированного `W` даёт те же решения, что `avg`, поэтому отдельно не нужен — отметь это в docstring;
- отличие от остальных методов: при `W > 64` статистика захватывает шаги **предыдущих** окон той же записи. В начале записи, где шагов меньше `W`, статистика считается по имеющимся шагам;
- оценка окна (чтобы оценка оставалась **оконной**, как у всех методов): `S` — **максимум** скользящей статистики по позициям-целям этого окна. Окно аномально, если хотя бы в одной его позиции поток превысил порог;
- порог: `θ = percentile_p` оценок окон validation, посчитанных так же;
- сетка: `W ∈ {8, 16, 32, 64, 128, 256}` × агрегация `{avg, max}` × `p` (оконная сетка, как у `nll`). Строки тепловой карты — пары (агрегация, W);
- варианты: `stream_nll` и `stream_rank`.

### Склейка шагов в поток (главная тонкость)
- Использовать позиции окон в записи, которые уже есть в кеше после CALIBRATE_TRIM. Если их нет — добавить, той же функцией, что вычисляет позиции окон (без своей нарезки). Позиция цели шага `t` окна = позиция окна + 1 + t.
- **Test:** окна идут без перекрытия, кроме последнего, прижатого к концу записи. **Validation:** окна с шагом `seq_step` перекрываются. Для потока каждой позиции нужна **ровно одна** оценка: брать оценку из **первого** окна, покрывающего позицию; остальные дубликаты отбросить. Объясни в docstring, что модель обнуляет контекст в начале каждого окна, поэтому оценки одной позиции из разных окон могут отличаться, и почему выбрано первое окно.
- Оценка окна `S` вычисляется для **исходных** окон (test — те же окна, что у остальных методов; val — те же окна, что для перцентиля у `nll`), по скользящей статистике в их позициях.
- Фильтры CALIBRATE_TRIM (`--trim_head_sec`, `--attack_max_sec` и т.д.) применяются к **окнам оценки**, а не к потоку: поток считается по всей записи, затем исключённые окна просто не участвуют в метриках. Отметь это в docstring.
- Векторизация: скользящее среднее — через кумулятивную сумму, скользящий максимум — через `scipy.ndimage.maximum_filter1d` или эквивалент. Никаких Python-циклов по позициям.

## Подписи (украинский, по правилу CLAUDE.md)
| Метод | Подпись |
|---|---|
| `cnt_nll` | `Кількість аномальних викликів у вікні (NLL)` |
| `cnt_rank` | `Кількість аномальних викликів у вікні (ранг)` |
| `stream_nll` | `Ковзне вікно по потоку викликів (NLL)` |
| `stream_rank` | `Ковзне вікно по потоку викликів (ранг)` |

Оси:
- `cnt`: Y — `Мінімальна кількість аномальних викликів у вікні, m`, X — как у `run`;
- `stream`: Y — `Агрегація та довжина ковзного вікна, W (викликів)` (метки строк вида `сер., 32` / `макс., 128`), X — как у `nll`.

## Остальное
- `--methods` по умолчанию теперь включает все восемь методов: `nll topk run_nll run_rank cnt_nll cnt_rank stream_nll stream_rank`.
- Все критерии (`fbeta`, `recall_at_fpr`, ограничение `--max_fpr`), проверка `degenerate`, pAUC@0.05, парный бутстреп к `nll`, сводка `hids-calibrate-summary` — для новых методов так же. Для pAUC у `cnt` кривая строится по `C` при шаговом `p`, выбранном на calib (как у `run`); у `stream` — по `S` при `(агрегация, W)`, выбранных на calib.
- Версия формата кеша не меняется, если позиции окон уже есть; иначе повысить.

## Тесты
- `cnt` при `m = 1` совпадает с `run` при `m = 1`;
- `cnt`: векторный подсчёт совпадает с наивным на случайных матрицах; гистограммный TP/FP для всех `m` совпадает с прямым;
- `stream`: склейка позиций на ручном примере — test без перекрытий плюс прижатое последнее окно, val с шагом 32: каждая позиция ровно один раз, взята из первого окна;
- `stream`, `avg` при `W = 1`: `S` равно максимуму оценок шагов окна (= `nll` с `q = 1.0`), проверить совпадение;
- скользящие avg/max совпадают с наивной реализацией;
- регрессия: результаты прежних четырёх методов не меняются.
